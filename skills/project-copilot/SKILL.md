# 项目搭档

1. 明确用户要盘点、交接还是继续执行，并确定交付物。用户指定工作区时先核对该处的项目说明与 `AGENTS.md`。项目含糊、有多个副本或需要长期维护盘点时，优先读取同一 Skill 目录下的 `references/project-map.local.md`。需要创建地图时使用[项目地图模板](references/project-map.example.md)。
2. 有多个候选时，先核对实际路径和目录链接。对 Git 仓库查看 `git worktree list --porcelain`、Git 公共目录、分支、HEAD 和工作树状态，再用交接记录、提交关系及任务范围选择。不同 Git 公共目录也可能属于同一项目的不同副本。对无 Git 或尚未提交的目录，核对入口、文档及可复跑产物。仍有多个合理修改目标且会改变交付时，请用户选择。
3. 读取最相关的源码、交接和验收记录。给历史证据注明日期与适用版本。判断服务、部署、数据或发布状态时，以对应环境的当前证据为准。保护未提交工作、运行数据和已有交付件。
4. 按交付物选择工作流。实现、修复或验收软件可使用 `project-delivery`，视频、图片、排版文档或演示稿可使用 `creative-delivery`。若相应 Skill 未安装，沿用可用的专业工具和项目内流程。
5. 交接时给出选定路径、分支或交付物版本、选择依据、已验证事项和下一步。用户已要求执行且目标明确时，继续完成该任务。

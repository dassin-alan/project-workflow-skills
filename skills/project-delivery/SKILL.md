# 研发交付

1. 从用户请求提取可观察的验收行为。确认工作区、分支和未提交变更，遵循项目 `AGENTS.md`、锁文件和现有运行入口。项目副本或基线有歧义时，可使用 `project-copilot` 定位。
2. 优先修改实际入口背后的最小必要范围，复用已有流程。修复先定位可观察的故障，再在原入口验证。按需调用已有的调试、浏览器验证或代码审查 Skill。项目有已锁定的界面、数据契约或用户流程时，核对相关回归。
3. 从定向验证开始，根据影响范围运行项目已有的集成或发布门禁。记录实际执行的命令、结果和适用版本。有状态的验证用适当的隔离输入，保留已有数据和历史验收记录。
4. 按项目性质选取证据。
   - **科研应用**核对服务端数据来源、版本、选证和可见性。界面展示、样本导入、目标数据库和科学结论各自需要相应证据。
   - **模型或消息集成**先查本地或模拟路径，再按项目约束和当前授权处理真实请求。记录真实请求、计费状态、机器评测和人工验收的覆盖。调用结果或用量不明时先查已有记录，仅在已批准范围内重试。诊断输出隐去凭据和私密消息。
   - **网站、桌面、移动端或游戏**按目标平台验证用户实际入口。构建、浏览器、真机、设备性能和人工审核分别以对应证据为准。
5. 给出可打开的文件或工作区、运行方法、验证结果和影响使用的限制。注明未运行、失败、环境阻塞或待人工验收事项。发布时使用与候选版本相符的门禁证据，并遵循当前授权。
